# Asset Pipeline & Art-Swap System

> How icons, backgrounds, UI chrome and future custom art flow into the game — designed around the
> user's requirement: **every item/armor/weapon/monster must be individually re-skinnable later**
> without code changes.

## 1. Inventory (what we have today, in `game_assets/`)

| Asset | Contents | Use |
|---|---|---|
| `UI/Backgrounds/*.png` (23) | tavern, arena, guild, dungeons, both shops, stable, pets, patrol + **14 mission scenes** — low-poly 3D renders, warm palette | screen backdrops & battle stages (`content-plan.md` §1 mapping) |

## 2. Icons — game-icons.net (user-specified source)

- **Vendored, not hotlinked:** chosen SVGs committed under `public/assets/icons/<category>/<name>.svg`
  with a generated manifest (`src/data/iconManifest.ts`) — build fails on unknown `iconId`.
- Recolor via CSS (`currentColor` normalization pass when vendoring) so rarity tinting/theming is
  free; rendered inside the rarity backplate component.
- **License: CC BY 3.0 → attribution required:** `CREDITS.md` + in-game Settings → Credits screen
  list game-icons.net authors (per-icon author tracked in the manifest), Kenney (CC0, credited as
  courtesy), fonts, and the user's own art. This is a 1.0 release-gate item (Roadmap P18).
- Estimated need: ~140 icons at 1.0 (item bases ~90, UI/currency/nav ~35, pets/misc ~15).

## 3. The art-override system (the user's future art drops in file-by-file)

Every visual entity resolves art through one function:

```
resolveArt(entity): AssetRef
  1. entity.artOverride set && file exists in manifest → /assets/art/<path>.png
  2. else → icon composition (iconId + rarity backplate)   // items, pets
       or archetype placeholder (monsters: silhouette card + zone tint)
```

- `public/assets/art/` mirrors content IDs: `art/items/<itemBaseId>.png`,
  `art/sets/<setId>/<piece>.png`, `art/monsters/<monsterId>.png`, `art/pets/<petId>.png`.
  **Dropping a correctly-named file + one manifest line activates it** — no component changes, by design.
- Art manifest is a typed module regenerated by `npm run assets:manifest` (scans folders, verifies
  dimensions, updates types). CI verifies manifest ↔ filesystem consistency.
- Bot "players" intentionally have **no** per-bot art (class portraits only — user rule).
- Recommended source spec for future art (documented for the user): items 256×256 PNG,
  transparent, centered subject ~80% frame; monsters 512×512 bust or full; consistent low-poly
  faceted style matching class portraits; light source top-left.

## 4. Backgrounds & performance

Backdrops are 2730×1536 → build generates responsive variants (1920/2560 + blur-up LQIP) via a
vendoring script; screens lazy-load their backdrop with a token-colored placeholder fade (no
white flashes). Battle scenes reuse the already-loaded zone backdrop. Total initial payload
excludes all backdrops (architecture §5 budget).

## 5. Ambient animation over static art

Backdrops get life via layered effects, not new assets: fireplace glow pulse (radial gradient
blend), dust motes / ember particles (canvas layer), lantern flicker (CSS), parallax on
battle-scene push-ins. One `<AmbientStage>` component takes a backdrop + effect recipe from the
screen config.

## 6. Sound (Q13 answered: approved)

- **SFX (1.0, Phase 17):** ~20 sounds (UI ticks, coin, forge strike, hit/crit/block/dodge,
  victory sting, loot/gacha reveal, level-up) from CC0 packs (Kenney audio), one `useSfx` hook
  with per-category throttling, master toggle + volume in Settings. Lazy-loaded after first
  interaction (autoplay policies; also keeps initial bundle clean).
- **Background music — user drop-in (Q13 requirement):** the game checks for
  `public/assets/audio/bgm.mp3` at startup. If present → looping background music with its own
  Settings row (toggle + volume, independent of SFX), gentle fade-in on start and fade-out/in on
  tab blur/focus. If absent → silence, zero errors, Settings row hidden. Swapping the file is the
  whole workflow — no code, no manifest entry. (Optional later: `bgm_<place>.mp3` per-screen
  variants; documented as post-1.0.)
